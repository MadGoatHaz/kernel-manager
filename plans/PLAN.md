- **Chosen:** new master SVG at repo root `org.archlinux.KernelManager.svg` = the scx-manager dial geometry verbatim (chip + circular dial + 3 ticks + upper-left needle + center dot; stroke-based; transparent background) with the accent recolored `#3584E4` → **`#F57F17`** (amber/gold = "core processing"; distinct from both the CachyOS green `#0BAC66`/`#11E388` and scx-manager blue). - **Rejected:** (a) keep the green artwork — user: "this is its own project now"; (b) a free-form new design — the user locked the scx-manager gauge geometry; (c) any other accent — `#F57F17` was the user's spec.

### D2 (Req #2) — repo-add = Option B (add + `pacman -Sy`) through the existing pkexec layer
- **Chosen:** context action **"Add repo '<repo>'"** offered for a curated pacman-repo kernel whose repo is not enabled (repo taken from the **table entry** — never user text; AUR excluded via `classify_repo`; already-enabled ⇒ no action). Click = Yes/No confirm → **`utils::add_repo_to_pacman_conf(repo)`** (new, `alpm_utils`) builds the single command `"$KM_HELPER_DIR/repo_add.sh '<repo>'"` and runs it via **`runCmdTerminal(cmd, true)`** — i.e. terminal-helper → `pkexec /usr/lib/kernel-manager/rootshell.sh` → root bash executes the helper. **No new polkit action and no new `exec.path`** (the pkexec target stays `rootshell.sh`; `auth_admin` as today — the user said pkexec, NOT sudo). New helper `src/repo_add.sh` (installed next to `rootshell.sh`, one CMake install block): static allowlist `cachyos | chaotic-aur | liquorix` with their official Server URLs (anything else ⇒ exit 1 — no injection possible at either layer) → **back up `/etc/pacman.conf` to `.bak-<epoch>` before the first modification** → **idempotent** (active `[repo]` section ⇒ skip append, no backup) → append `[repo]` + `Server =` lines → **`pacman -Sy`** (append and already-enabled paths alike — the DB refresh is what makes the kernel immediately installable) → the existing "Press enter to exit" keeps the terminal open on the result. C5 then re-parses the alpm handle + re-fetches + rebuilds the tree (the new row becomes live).
- **C++ guards (defense in depth, unit-tested):** `add_repo_to_pacman_conf` rejects empty repo, `aur`, a repo absent from the curated table's `install_repo` set, or any shell-metacharacter violation (`^[a-z0-9-]+$`) with a non-zero rc **without launching** (injected `RepoCmdRunner` per the k8 `CommandRunner` precedent).
- **Rejected:** (a) Option A — tell the user to edit pacman.conf by hand (user chose B); (b) pkexec'ing the new script directly — would need a second policy action + second installed file for privilege; the rootshell layer already exists and is the single audited path; (c) `sudo` — not the project's privilege model (WU-2 polkit, GPL-3.0 distro tooling); (d) append without backup; (e) skip `pacman -Sy` (kernel not installable until the DB refresh).
- **Server URLs (implementer verifies against official docs at C6 time, fetch evidence in the chunk log):** cachyos `https://repo.cachyos.org/$arch/$repo` (+ openrepo `https://openrepo.cachyos.org/$arch/$repo`); chaotic-aur `https://aur.chaotic.cx/$repo/$arch` (+ `https://aur2.chaotic.cx/$repo/$arch`); liquorix `https://liquorix.net/repos/packman/arch/$repo/$arch`. Official `core/extra/community/multilib` are never addable (base-install repos; a system missing them is outside scope — the script's allowlist omits them).
